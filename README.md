# HWEB - Unified Frontend

HWEB is the unified frontend interface for the Hanoled ecosystem. It consolidates the user interfaces of **Hanoled**, **HCBT** (Computer Based Testing), and **HCORE** into a single, cohesive Next.js web application.

## Overview

This project serves as the central hub for all user interactions, streamlining the experience for students, teachers, parents, and administrators across the Hanoled platform.

### Key Features

- **Unified Authentication:** Centralized sign-in flow powered by the HCORE Identity backend, with a shared `SignInForm` behind dedicated audience pages (`/signin/student`, `/signin/staff`, `/signin/parent`). Server error text is never surfaced to users; messages come from a safe, tested mapping (`lib/sign-in-errors.ts`).
- **Role-Based Dashboards:** Context-aware dashboards tailored for Owners, Admins, Teachers, Parents, and Students.
- **Deeply Integrated CBT:** The full exam lifecycle in-product — theory and objective questions (2–6 choices, A–F), a theory question designer, student exam taking with offline CBT sync, teacher marking of typed theory answers, per-exam item analysis, and late-submission review.
- **HCBT Edge Appliance UI:** The `/cbt` experience doubles as the appliance interface. With `NEXT_PUBLIC_EDGE_MODE=1`, `npm run build:edge` produces a static export (`edge-ui` project) served directly by the appliance. `EDGE_MODE` branches reframe the UI as "This Device" with no suite chrome.
- **Data Protection (NDPA):** Personal-data download, erasure, and retention screens under `(marketing)/data-protection`, aligned to the Nigeria Data Protection Act.
- **Teacher Subject Scoping:** Teachers see only their assigned subjects and can only create exams for those subjects (via HCORE teaching assignments).
- **Well-Tested Core:** Playwright e2e suites run against fake HCORE/HSMS/HCBT backends (`e2e/mock-api.mjs`), plus unit tests for the tricky lib modules (`lib/__tests__` — offline sync, sign-in errors, password policy, theory answers, and more).
- **Responsive Throughout:** Phone and tablet sweeps are part of the e2e cadence; navigation collapses into a drawer below 1024px.

## Tech Stack

- **Framework:** [Next.js 16.3](https://nextjs.org/) (App Router, Turbopack)
- **AI-ready:** `AGENTS.md` generated by Next.js for coding agents
- **Styling:** [Tailwind CSS v4](https://tailwindcss.com/)
- **Components:** [shadcn/ui](https://ui.shadcn.com/), Radix UI & Base UI
- **State Management:** [Zustand](https://zustand-demo.pmnd.rs/) + [TanStack Query](https://tanstack.com/query)
- **Forms & Validation:** [React Hook Form](https://react-hook-form.com/) + [Zod](https://zod.dev/) v4
- **Observability:** [Sentry](https://sentry.io/) (`@sentry/nextjs`, client + server + edge configs)
- **Data Fetching:** Custom API wrapper with automatic token refresh (`apiFetch`)
- **Testing:** [Vitest](https://vitest.dev/) (unit), [Playwright](https://playwright.dev/) (e2e, Chromium against mock backends)

## Project Structure

```
Hweb/
├── app/
│   ├── (auth)/               # Auth pages: signin (student/staff/parent), signup, invite accept, reset
│   ├── (marketing)/          # Public pages: landing, features, hcbt, data-protection, privacy, terms
│   ├── admin/                # Platform admin (hosted, schools, pipeline, payments, support)
│   ├── actions/              # Server actions
│   ├── admissions/           # Public admissions portal
│   ├── cbt/
│   │   ├── admin/            # CBT admin dashboard (exams, marking, item analysis, edge devices)
│   │   ├── student/          # Student exam interface
│   │   └── layout.tsx        # CBT layout with auth check
│   ├── dashboard/
│   │   ├── school/[slug]/    # School-specific dashboards
│   │   └── layout.tsx        # Subscription check + product routing
│   └── welcome/              # Welcome hub (deterministic candidate reveal via cookie, no render-time fetch)
├── edge-ui/                  # Static-export build of the CBT UI for the HCBT Edge Appliance
├── components/               # Reusable React components
├── e2e/                      # Playwright suites + shared fake backend (mock-api.mjs)
├── hooks/                    # Custom React hooks (useAuth, useOrganization)
├── lib/                      # Domain logic
│   ├── api.ts                # Shared API client, 401→refresh→signin chain, EDGE_MODE flag
│   ├── api-cbt.ts            # CBT-specific API calls
│   ├── cbt-offline.ts        # Offline exam capture + queue
│   ├── cbt-sync.ts           # Offline submission sync to the cloud
│   └── sign-in-errors.ts     # Safe error-text mapping (never leaks server messages)
├── services/                 # Service layer
└── store/                    # Zustand state stores
```

## Environment Variables

### Required

| Variable | Description | Local | Production |
|----------|-------------|-------|------------|
| `NEXT_PUBLIC_HCORE_URL` | HCORE backend API URL | `http://localhost:4000` | `https://core-api.hanoled.com` |
| `NEXT_PUBLIC_HSMS_URL` | HSMS backend API URL | `http://localhost:3001` | `https://api.hanoled.com` |
| `NEXT_PUBLIC_HCBT_URL` | HCBT backend API URL | `http://localhost:4002` | `https://cbt-api.hanoled.com` |

### Optional

| Variable | Description | Example |
|----------|-------------|---------|
| `NEXT_PUBLIC_GOOGLE_CLIENT_ID` | Google OAuth Client ID | `186668766929-xxx.apps.googleusercontent.com` |
| `NEXT_PUBLIC_EDGE_MODE` | Static edge-appliance export (set to `1` inside `edge-ui`) | `1` |

### Vercel Deployment

For Vercel deployments, set these in **Settings → Environment Variables**:

```env
NEXT_PUBLIC_HCORE_URL=https://core-api.hanoled.com
NEXT_PUBLIC_HSMS_URL=https://api.hanoled.com
NEXT_PUBLIC_HCBT_URL=https://cbt-api.hanoled.com
```

**Important:** HCORE's `CORS_ORIGIN` must include your Vercel deployment URL:
```
https://hweb-three.vercel.app,https://accounts.hanoled.com,https://core-api.hanoled.com
```

## Getting Started

### Prerequisites
- Node.js 20+
- HCORE backend running on port 4000
- HSMS backend running on port 3001 (optional)
- HCBT backend running on port 4002 (optional)

### Installation

```bash
git clone https://github.com/Hanoled-codebase/HWEB.git
cd HWEB
npm install
```

### Configure Environment

```bash
cp .env.example .env.local
# Edit .env.local with your backend URLs
```

### Run Locally

```bash
npm run dev
# Opens on http://localhost:3000
```

### Tests

```bash
npm run test        # Vitest unit tests (lib/__tests__)
npm run test:e2e    # Playwright e2e against fake backends (no real data touched)
```

## CBT Admin Dashboard

The CBT admin page (`/cbt/admin`) provides a role-driven interface:

- **Admin users**: See all exams, can publish/assign exams, full subject access
- **Teacher users**: See only assigned subject exams, can create drafts only, subject selector shows assigned subjects only

### Features by Role

| Feature | Admin | Teacher |
|---------|-------|---------|
| View exams | All org exams | Assigned subjects only |
| Create exam | Any status | Draft only, assigned subjects |
| Publish exam | ✅ | ❌ (shows "awaiting admin approval") |
| Assign exam | ✅ | ❌ |
| Theory designer & marking | ✅ | ✅ (own subjects) |
| Item analysis | ✅ (per exam) | Viewer |
| Late-submission review | ✅ | ✅ |

## MVP Scope Notes

Hweb shipped as an MVP with a deliberately trimmed scope. The following are **parked for post-v1** (the UI routes exist and redirect to "coming soon" states rather than silently failing):

- **Payments** — bursary keeps paper records until payments go live
- **Scratch cards** — serial + PIN result unlocking; the page exists but sits behind a post-launch gate
- **Messaging** — in-product messaging is post-v1
